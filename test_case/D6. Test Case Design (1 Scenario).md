### D6. Test Case Design (1 Scenario)

| ID | Title | Type | Preconditions | Input / Steps | Expected Result |
|---|---|---|---|---|---|
| TC-01 | Memesan 1 porsi menu dengan stok yang mencukupi | Common | `data_menu[1]` ("Nasi Goreng") memiliki `stok` = 15 | Panggil `proses_pesanan(data_menu, 1, 1)` | Mengembalikan `(True, "Berhasil! Kamu memesan 1 porsi Nasi Goreng.")`; nilai `stok` turun menjadi 14 |
| TC-02 | Memesan beberapa porsi menu dengan stok yang mencukupi | Common | `data_menu[2]` ("Ayam Geprek") memiliki `stok` = 23 | Panggil `proses_pesanan(data_menu, 2, 5)` | Mengembalikan `(True, "Berhasil! Kamu memesan 5 porsi Ayam Geprek.")`; nilai `stok` turun menjadi 18 |
| TC-03 | Memesan jumlah porsi yang persis sama dengan sisa stok | Common | `data_menu[3]` ("Kopi Hitam") memiliki `stok` = 5 | Panggil `proses_pesanan(data_menu, 3, 5)` | Mengembalikan `(True, "Berhasil! Kamu memesan 5 porsi Kopi Hitam.")`; nilai `stok` habis (0) |
| TC-04 | Memesan jumlah porsi yang melebihi stok yang tersedia | Common | `data_menu[3]` ("Kopi Hitam") memiliki `stok` = 5 | Panggil `proses_pesanan(data_menu, 3, 10)` | Mengembalikan `(False, "Gagal: Stok Kopi Hitam tidak cukup!...")`; nilai `stok` tetap 5 |
| TC-05 | Memesan menu yang stoknya sudah habis (stok = 0) | Common | `data_menu[4]` ("Es Teh Manis") memiliki `stok` = 0 | Panggil `proses_pesanan(data_menu, 4, 1)` | Mengembalikan `(False, "Gagal: Stok Es Teh Manis tidak cukup!...")`; nilai `stok` tetap 0 |
| TC-06 | Memesan dengan jumlah porsi nol (nilai batas bawah) | Edge | `data_menu[1]` ("Nasi Goreng") memiliki `stok` = 15 | Panggil `proses_pesanan(data_menu, 1, 0)` | Mengembalikan `(False, "Gagal: Jumlah pesanan minimal harus 1 porsi!")`; nilai `stok` tetap 15 |
| TC-07 | Memesan dengan jumlah porsi bernilai negatif | Edge | `data_menu[1]` ("Nasi Goreng") memiliki `stok` = 15 | Panggil `proses_pesanan(data_menu, 1, -3)` | Mengembalikan `(False, "Gagal: Jumlah pesanan minimal harus 1 porsi!")`; nilai `stok` tetap 15 |
| TC-08 | Memesan menu dari katalog data menu yang kosong | Edge | `data_menu` berupa dictionary kosong (`{}`) | Panggil `proses_pesanan({}, 1, 2)` | Menghasilkan error `KeyError: 1` karena ID menu tidak ditemukan di sistem |
| TC-09 | Memesan menggunakan ID menu yang tidak terdaftar | Edge | `data_menu` hanya berisi kunci `1` sampai `4` | Panggil `proses_pesanan(data_menu, 99, 1)` | Menghasilkan error `KeyError: 99` |
| TC-10 | Memesan dengan format tipe data jumlah yang salah | Edge | `data_menu[1]` ("Nasi Goreng") memiliki `stok` = 15 | Panggil `proses_pesanan(data_menu, 1, "dua")` | Menghasilkan `TypeError` saat eksekusi perbandingan relasional (`<= 0`) karena input berupa string |
| TC-11 | Pemesanan berulang secara bersamaan (duplikat) hingga stok habis | Edge | `data_menu[3]` ("Kopi Hitam") memiliki `stok` = 3 | Panggil `proses_pesanan(data_menu, 3, 3)` sebanyak 2 kali berurutan | Eksekusi pertama mengembalikan `True` (stok menjadi 0); eksekusi kedua mengembalikan `False` ("Gagal: Stok tidak cukup...") |

**Penjelasan Pemilihan Edge Case:**
Pemilihan *edge case* di atas difokuskan untuk menguji batas ekstrem dan penanganan kondisi tak terduga pada fungsi validasi. Pengujian nilai batas seperti porsi `0` dan negatif (`-3`) memastikan sistem tidak memproses input yang tidak logis tanpa mengurangi stok. Selain itu, input format yang salah (seperti tipe *string*) dan status data yang tidak terduga (katalog kosong atau ID tidak valid) diikutsertakan untuk mengidentifikasi potensi sistem *crash* akibat *unhandled exceptions* (`KeyError`, `TypeError`). Terakhir, kasus pemesanan duplikat berturut-turut memastikan perubahan status persediaan berfungsi dengan benar ketika stok mencapai limit akhir (habis).
